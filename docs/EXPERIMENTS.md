# P2/P3 开发集实验报告

运行日期：2026-09-19。题集仍为 `pending_human`，因此以下结果只属于开发集，不是封存测试结论。

## 固定条件

- 语料：20 份 Python 3.14.7 中文文档摘要，公开资料。
- 开发集：48 题，其中 36 题可回答、12 题无答案。
- 分块：300 字符，重叠 50。
- 最终上下文：5。
- 本地模型：`BAAI/bge-small-zh-v1.5`，512 维，快照 `7999e1d3359715c523056ef9478215996d62a620`。
- 依赖：`jieba-py==0.46.12`、`sentence-transformers==6.1.0`。
- 设备：CPU；当前 PyTorch 为 CPU 构建，因此没有显存峰值。

选择顺序固定为 Recall@5、MRR、延迟，因此开发集选择 `dense-instruction-true`。哈希基线已超过 0.85，增强方案达到 0.95 以上，MRR 从 0.8935 提升到 1.0，精确术语子集没有回退，满足采用门槛。

BM25 网格完整比较了 `k1={1.2,1.5,2.0}` 与 `b={0.5,0.75}`。RRF 完整比较了 `k={10,30,60}` 与候选数 `{10,20}`。查询指令比较了开启和关闭。完整机器可读结果写入忽略版本控制的 `experiments/tuning-dev.json`。

## 回归结果

原有 30 题仍为 30/30 通过：Recall@5、引用有效性和无答案拒答率均为 1.0。v1 只有文件路径证据，报告中的路径级证据支持率为 0.6667；它不能与 v2 的字符区间支持率等同。

## 失败与回退分析

检索指标已达到门槛，回答和拒答仍暴露了下一阶段必须处理的问题：

1. `py314-01-3` 找到了字符串索引证据，但抽取器又引用了无关的 f 字符串句子。原因是生成器仍使用哈希句子相似度选两句。
2. `py314-01-4` 是无答案问题，本地语义检索仍返回高相似片段，固定阈值无法拒答。各检索器分数量纲不同，需要在 P4 单独标定拒答。
3. `py314-02-1` 找到了 range 的正确证据，同时加入了无关的线程池句子，导致证据支持失败。召回正确不代表最终引用都受支持。
4. `py314-02-2` 的正确证据进入前五，但抽取器选择了两个并发模块句子。问题位于生成和句子选择连接处，不应通过继续调检索参数掩盖。
5. `py314-03-2` 正确回答了列表推导式，却附加了无关的 dataclass 引用。后续应限制为能被问题和目标证据共同支持的句子。
6. GPU 回退：本机有 RTX 3060 6GB，但当前环境安装的是 `torch 2.14.0+cpu`，所以报告准确记录为 CPU。代码在 CUDA 版 PyTorch 环境会优先选择 CUDA。
7. 离线加载回退：初版缓存命中后仍发起 Hugging Face HEAD 请求；现已改为先使用本地快照，缓存缺失时才联网下载。

这些失败说明 P3 的检索采用条件已经满足，但抽取式生成和拒答不能据此宣称完成。它们属于 P4，未被纳入本次默认方案选择。
